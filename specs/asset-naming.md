# 素材命名规范（写死）

```
assets/<类别中文>/<名称中文>[_<状态中文>]<序号>.png
```

例：`食物/牛排1.png`（无状态）、`食物/蘑菇_烤2.png`（带状态）。

- 类别：`食物`、`道具`、`场景`、`UI`。目前只启用 `食物`，新增类别要先加进 `factory/check_assets.py` 的白名单。
- 名称：中文，不含空格和标点。同一名称+状态多个序号 = 同一物件的不同角度/切法，下游随机取一张即可。
- 状态（可选，下划线隔开）：`生`、`切块`、`烤`、`炙烤`、`炒`。无状态的物件 manifest 里记为 `默认`。新状态先加到本表。
- 英文源名对照：raw→生，chopped→切块，roasted→烤，grilled→炙烤，sauteed→炒。
- 序号：从 1 开始连续，不补零。`牛排1.png`、`牛排2.png`，不允许跳号。
- 文件：PNG、RGBA、正方形、边长 512–2048（生图默认 1024）、四角像素 alpha 必须为 0、主体占比 40%–95%。
- 一张图只放一个物件。整张多物件的"拼图表"用 `factory/split_sheet.py` 拆成单件后再入库。
- `assets/manifest.json` 由 `factory/check_assets.py` 自动生成，不要手改。游戏代码只读 manifest，不猜文件名。
- 媒体源文件（录屏、原始生图）不进仓库，只登记 SHA-256。

## manifest.json 结构

```json
{"食物": {"蘑菇": {"生": ["assets/食物/蘑菇_生1.png"], "烤": ["assets/食物/蘑菇_烤1.png"]}}}
```

## 源图

多物件拼图表原图放 `source/sheets/<英文名>/`，不入库到 assets，`source/sheets.sha256` 登记哈希。
